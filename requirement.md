Cab Driving App – Requirements Specification
1. Project Overview

The Cab Driving App is designed to provide a simple and convenient platform for users to book cabs, view driver details, track ride status, and manage payments and ride history.

This project is planned in two development increments: Sprint 1 and Sprint 2.

2. Functional Requirements

Functional requirements describe what the application should do.

Sprint 1 – User Interface and Cab Booking

FR-01: User Login
- The application shall provide a login page.
- Users shall be able to enter their email or username and password.

R-02: User Registration
- The application shall provide a registration page for new users.

FR-03: Home Page
- The application shall display the main cab booking screen.

FR-04: Pickup Location
- Users shall be able to enter or select their pickup location.

FR-05: Drop Location
- Users shall be able to enter or select their destination.

FR-06: Cab Selection
- The application shall display available cab types: Mini, Sedan, and SUV.

FR-07: Fare Estimation
- The application shall display an estimated fare before booking.

FR-08: Book a Cab
- The application shall provide a Book Cab button to initiate a ride booking.

Sprint 2 – Ride Management and Payment

FR-09: Driver Details
- The application shall display the driver's name, rating, vehicle number, and cab type.

FR-10: Ride Confirmation
- The application shall display booking confirmation details.

FR-11: Ride Status
- The application shall display the current ride status, such as Confirmed, Arriving, or Completed.

FR-12: Estimated Arrival
- The application shall display an estimated driver arrival time.

FR-13: Pickup and Drop Details
- The application shall display pickup and destination addresses.

FR-14: Payment
- The application shall display payment options such as UPI and Cash.

FR-15: Ride History
- The application shall display previous rides, dates, fares.
- FR-16: Ride Cancellation
- The application shall provide an option to cancel a booking.

3. Non-Functional Requirements

Non-functional requirements describe how the application should perform.

- **Usability:** The interface shall be simple and easy to understand.
- **Performance:** Screens should load promptly under normal operating conditions.
- **Security:** User credentials and personal information shall be protected.
- **Reliability:** The application should handle expected user actions consistently.
- **Compatibility:** The interface should be designed to support mobile screen sizes.
- **Maintainability:** The project files should be organized and managed using Git.
- **Accessibility:** Text and buttons should be readable and easy to interact with.

4. Software and Tools Requirements

- Operating System: Windows, Linux, or macOS.
- Wireframing Tool: diagrams.net (draw.io).
- Version Control: Git.
- Repository Hosting: GitHub.
- Code Editor: Visual Studio Code (optional).

5. Hardware Requirements

- Computer or laptop.
- Internet connection for GitHub access.
- Web browser.
- Sufficient storage for project files.

6. User Interface Requirements

The application shall contain the following four main wireframe pages:

1. **Login & Registration:** Login fields, registration option, and password recovery link.
2. **Cab Booking:** Pickup and drop locations, cab selection, estimated fare, and booking button.
3. **Ride Details:** Driver information, vehicle details, arrival time, route, and ride status.
4. **Payment & History:** Fare summary, UPI and Cash options, payment button, and previous rides.

7. Sprint Plan

| Sprint | Planned Requirements |
|---|---|
| Sprint 1 | FR-01 to FR-08: Login, registration, home, and cab booking |
| Sprint 2 | FR-09 to FR-16: Driver details, ride management, payment, and history |

8. Acceptance Criteria

- All four wireframe pages are created and saved.
- Each page contains the planned interface elements.
- Both development increments are documented.
- Project files are committed to the local Git repository.
- Changes are pushed to GitHub.
- Repository changes can be reviewed and Git status checked.

9. Current Project Status

Current stage: Wireframe design and requirements planning.

The functional requirements describe the planned application behavior. Actual login, booking, GPS tracking, and payment functionality will require implementation and testing.

10. Future Enhancements

- GPS-based live tracking.
- Real-time cab availability.
- Secure payment gateway integration.
- Push notifications.
- Driver and passenger ratings
